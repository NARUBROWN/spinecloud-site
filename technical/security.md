# 보안과 데이터

Spine Cloud의 보안은 인증, 소유권 확인, 결과물 보호와 실행 환경의 경계를 함께 다룹니다. 아래 항목은 각각의 구현과 검증 범위가 다릅니다.

## 계정과 CLI 인증

CLI 로그인은 웹에서 승인하는 일회용 코드를 사용합니다. 코드는 5분 동안 유효하며 기기 비밀값을 가진 CLI만 승인 결과를 받을 수 있습니다. 웹과 CLI는 별도 세션을 사용합니다.

개발 CLI와 운영 API, 인증 서비스, 승인 화면을 연결한 시험에서 인증 없는 승인, 다른 기기의 비밀값, 반복 승인과 승인 결과의 재수령이 거부됐습니다. 현재 요청 제한은 API 프로세스별로 적용됩니다. 복제본을 늘리기 전 공유 요청 제한과 악용 감시가 필요합니다.

## 앱 접근과 배포 결과물

관리 API는 앱과 배포 요청의 소유권을 확인합니다. 자체 예제의 운영 검증에서 다른 계정의 앱과 이력 접근 및 비공개 결과물 요청이 거부됐습니다. 이는 검증한 경로에 대한 결과입니다.

배포 결과물은 gzip으로 압축하고 AES-256-GCM으로 암호화해 Supabase Storage의 비공개 버킷에 저장합니다. 에이전트는 복호화 후 해시와 형식을 다시 확인합니다. 키 교체와 복구, 서비스별 최소 권한 자격 증명은 운영 전 추가 검증이 필요합니다.

## 환경 변수와 로그

로컬 구현에서는 환경 변수 값을 AES-256-GCM으로 암호화하고 앱 ID와 변수 이름을 인증 데이터로 결합합니다. 소유자는 등록된 이름을 확인할 수 있지만 저장한 값은 다시 조회할 수 없습니다. 변경 사항은 다음 배포의 스냅샷에 반영하도록 구현했습니다. 이 경로는 운영 환경에 아직 적용되지 않았습니다.

애플리케이션 로그에는 앱이 직접 출력한 비밀값이 포함될 수 있습니다. 민감한 값을 로그에 출력하지 않도록 주의해야 합니다. 로컬 상태 수집 구현의 보관 동작은 [운영과 복구](./operations)에 설명합니다.

## 격리와 보안 한계

자체 예제에 대한 검증은 임의 고객 코드 사이의 격리, 호스트와 릴레이, 자격 증명 접근 차단을 입증하지 않습니다. 다중 사용자 격리와 실제 운영 배포 경로는 오픈 베타 전에 별도로 검증해야 합니다. 독립적인 보안 인증이나 감사, 침해 사고 대응 시간에 대한 보장은 현재 확인되지 않았습니다.

보안 문제 제보 채널과 대응 정책은 확정 후 공개해야 합니다. 이 문서의 기술적 보호 조치를 절대적인 안전 보장으로 해석하지 마세요.
