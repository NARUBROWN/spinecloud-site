# 架構與服務供應商

Spine Cloud 透過 CLI 接收部署請求，使用管理 API 與執行代理程式執行應用程式。下圖僅顯示邏輯路徑，不含憑證或內部位址。

<ArchitectureMap />

## 元件與供應商

| 元件 | 職責 | 已記錄環境 |
| --- | --- | --- |
| Spine CLI | 帳戶連結、建置和部署 | 開發者環境中的 Preview 開發版 CLI |
| 控制台 | 帳戶核准、應用程式和歷程 | Vercel 上的 React |
| 管理 API | 驗證、所有權、工作和狀態 | Railway |
| 身分與儲存 | 驗證、中繼資料和私人建置產物 | Supabase |
| 代理程式 | 查詢、驗證、執行和回報 | OCI 虛擬機器 |
| Portal | 將公開 HTTPS 流量轉送至應用程式 | 自行維運的中繼與通道 |

以上是範例驗證環境，公開測試的最終區域、資料位置和供應商責任尚未確定。

## 部署與流量

在瀏覽器核准一次性代碼後執行 `spine deploy`。API 檢查所有權和格式，加密並私人儲存產物。代理程式透過已驗證的 HTTPS 查詢並領取工作，解密後驗證雜湊和格式，再啟動應用程式。內部健康檢查與公開 HTTPS 檢查完成後記錄成功狀態和網址。請求已接收不代表應用程式已執行。

CLI、Railway、Supabase、OCI 和 Portal 的完整連線僅針對指定內部範例驗證。訪客流量經過 Portal 中繼與通道。HTTPS 輪詢不需要額外的入站管理連接埠；原環境的直接 SSH 連線逾時，原因尚未確定。

## 開發者須知

範例使用 `GET /health`；一般應用程式的確切契約、受支援 CLI 和平台須在測試前確定。也應考慮資料庫連線、金鑰輪替和日誌中的敏感資訊。單台 VM 故障可能影響多個應用程式，不保證高可用性或零停機部署。
