# アーキテクチャと提供事業者

CLIでデプロイを受け付け、管理APIと実行エージェントでアプリを実行します。図は認証情報や内部アドレスを含まない論理経路です。

<ArchitectureMap />

## 構成と提供事業者

| 構成 | 役割 | 記録された環境 |
| --- | --- | --- |
| Spine CLI | 連携、ビルド、デプロイ依頼 | 開発者環境のPreview開発CLI |
| ダッシュボード | アカウント承認、アプリと履歴 | Vercel上のReact |
| 管理API | 認証、所有権、ジョブと状態 | Railway |
| 認証とストレージ | 認証、メタデータ、非公開成果物 | Supabase |
| エージェント | ジョブ取得、検証、実行、状態報告 | OCI |
| Portal | 公開HTTPSをアプリへ転送 | 自社運用のリレーとトンネル |


## デプロイと通信

ブラウザでワンタイムコードを承認し、`spine deploy`を実行します。APIは所有権と形式を確認し、成果物を暗号化して非公開保存します。エージェントは認証済みHTTPSでジョブを取得し、復号、ハッシュと形式の確認後に実行します。内部ヘルスチェックと公開HTTPSの確認後に成功とアドレスを記録します。受付状態は実行成功を意味しません。

## 開発時の注意

DB接続と秘密情報の更新にも注意してください。
